# 0008: Security hardening 6b

Status: accepted (Stage 6b). Fixes the findings of the Stage 6a audit of `services/api` that were selected for this stage. Extends ADR 0007 (guarded transitions) for invitation accept.

## Context

The 6a audit was a read-only review of `services/api`. It found no classic IDOR (every `:id` route filters by the caller) but several trust and integrity gaps. This stage fixes a selected subset with one small change per finding. Money, agency role permissions, rate-limit storage and route-wide zod are out of scope (see "Remaining findings").

## Decision

| ID  | What changed                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| H1  | The client can no longer send `imageId`. A cover image (freelancer portfolio, agency cover) is a new `data:image/` upload, or a url that matches one of the caller's own stored rows, which reuses the stored `{imageId, url}`. Anything else is 400. Deletes only use ids from the caller's own previous rows. The agency avatar follows the same rule.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| M1  | `isAuthenticated` answers 403 when no account exists for the claimed role. `/auth/status` uses a non-enforcing `identifyAccount`; sign-up is unchanged. The socket.io handshake gets the same rule through `authenticateHandshake`, which rejects accounts that do not exist. A cached "no account" answer lives 30 seconds (`ACCOUNT_AUTH_NEGATIVE_CACHE_TTL_SECONDS`) while a cached account keeps 10 minutes, so a failed cache invalidation after sign-up costs a new user at most 30 seconds of 403s; sign-up still invalidates the entry.                                                                                                                                                                                                                                                                                                                                     |
| M3  | `live_url` / `liveUrl` must be an http(s) URL of at most 2048 characters; blank is treated as absent. Cover image urls are limited to the two forms in H1.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| M4  | `offset` (integer 0 to 10000) and `query`/`q` (max 100 characters) are capped by zod on `/freelancer/search`, `/agency/search` and `/client/marketplace/search`. The two public search routes get a per-IP limiter (60 per minute, in memory). Clerk lookups per result are unchanged.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| M5  | Conversation participants are built field by field: `participantType`, `name`, `avatarUrl`, `professionalTitle`, `companyName`. No `email`, `accountId` or `agencyId`. The name fallback is `Member`, not the email.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| M6  | Invite responses are identical for any email except two coded 409s for this agency only (`INVITEE_ALREADY_MEMBER`, `INVITATION_ALREADY_PENDING`). `notifiedInApp` is removed, and notifications are skipped for invitees that already belong to an agency. Invite, cancel and resend share a limit of 20 per hour per user. Resend has a 60 second cooldown (guarded `UPDATE` on `updated_at`, 429 `INVITATION_RESEND_COOLDOWN`).                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| M9  | `createAgency` rejects any existing membership (`ALREADY_IN_AGENCY`, 409) and maps both the member and the owner unique violations (`agency_members_freelancer_id_unique`, `agency_metadata_owner_id_unique`) to the same 409, so a lost race is never a 500. Accept and decline of an invitation is one guarded `UPDATE ... WHERE status = 'PENDING' RETURNING`; accept inserts the member in the same transaction. Zero rows gives 409 `INVITATION_ALREADY_HANDLED`; a unique violation gives `ALREADY_IN_AGENCY` and rolls the status back. **No migration:** the unique constraint on `agency_members.freelancer_id` already exists (`0000_init.sql`), and owners already have a `Founder` member row, so one membership check covers owners and members. The audit's "missing index" claim was wrong; the real gap was the unguarded accept and the unmapped unique violation. |
| M10 | A bid is rejected (403) when the job's client is the sender, or for agency bids any agency team member, before Connects are deducted. `createConversation` rejects (400) a recipient equal to the caller, and a proposal-based counterpart that is the caller or on the caller's agency team.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| L1  | `verifyToken` receives `authorizedParties` set to the CORS origin list (exact string match). Clock skew is unchanged.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| L2  | The admin `?token=` query token is accepted only on `/admin/logs/stream`; every other admin route takes the Bearer header only.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| L5  | A bad Stripe signature on the Connects webhook is `ApiError` 400.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| L7  | Only when `NODE_ENV=production`: Clerk, Stripe (including the webhook secrets) and the admin password and session secret are required, values containing `change-me` are rejected, `ADMIN_SESSION_SECRET` needs at least 32 characters, and CORS has no localhost fallback. Production also needs at least one dashboard origin (`CLIENT_DASHBOARD`, `FREELANCER_DASHBOARD`, `AGENCY_DASHBOARD`, `ADMIN_DASHBOARD`), each a valid http(s) URL, because an empty list would make L1 fail open (Clerk skips the `azp` check when `authorizedParties` is empty). Development, tests and CI are unchanged. The list is in `.env.example`.                                                                                                                                                                                                                                               |
| L8  | One Clerk client in `src/config/clerk.ts` (lazy, like the Stripe client). No `createClerkClient` outside `config/`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |

### Side effect to know about

`createUserRateLimiter` keyed on `authClaims`, which only `verifyBearerToken` sets; `isAuthenticated` sets `request.auth` instead, so a user limiter behind `isAuthenticated` fell back to per-IP. It now keys on `request.auth.userId`, then `authClaims`, then IP (the same Clerk subject). The existing user limiters (jobs, agency profile, messaging writes) sit behind `verifyBearerToken` and behave as before; the change matters for the new invite limiter, which sits behind `isAuthenticated`.

The pending invitations list (`GET /agency/team/invitations`) no longer returns an avatar (`avatarUrl` is always `null`), because the avatar was only present for registered emails and revealed registration.

## Client-visible contract changes

| Area                                      | Before                                                | After                                                                                                                     |
| ----------------------------------------- | ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| Cover image requests (freelancer, agency) | `imageId` accepted                                    | `imageId` ignored. Cover images only by upload (`data:image/`) or by echoing the caller's own stored url. Other urls: 400 |
| Agency avatar request                     | `imageId` accepted                                    | Same rule as cover images                                                                                                 |
| `live_url` / `liveUrl`                    | any string                                            | http(s) URL, at most 2048 characters, else 400                                                                            |
| Any `isAuthenticated` route               | claimed role accepted without an account              | 403 "An account for this role is required." (except `/auth/status` and sign-up)                                           |
| socket.io connect                         | connected without an account                          | rejected with 403                                                                                                         |
| Tokens without `azp`                      | accepted                                              | 401 when the CORS origin list is non-empty                                                                                |
| Conversation participant                  | included `email`, `accountId`, `agencyId`             | only the five public fields; the frontend may need a server-computed `isMe` later                                         |
| Invite response                           | `notifiedInApp`; 409 for members or pending elsewhere | no `notifiedInApp`; same 201 except the two same-agency 409s. Resend returns `data: null`                                 |
| Pending invitations list                  | `avatarUrl` set for registered emails                 | `avatarUrl` always `null`                                                                                                 |
| Resend invitation                         | unlimited                                             | 429 within 60 seconds; 20 invite/cancel/resend actions per hour per user                                                  |
| `POST /agency`                            | 409 only for an owned agency                          | 409 `ALREADY_IN_AGENCY` for any membership                                                                                |
| Accept or decline invitation              | unguarded status change                               | 409 `INVITATION_ALREADY_HANDLED` or `ALREADY_IN_AGENCY`                                                                   |
| Proposals and conversations               | bid on own job; conversation with self                | bid 403; conversation 400                                                                                                 |
| Search routes                             | unbounded `offset`, `query`                           | 400 above the caps; 429 over 60 requests per minute per IP on the two public routes                                       |
| Admin routes                              | `?token=` accepted everywhere                         | `?token=` only on `/admin/logs/stream`                                                                                    |
| Connects webhook, bad signature           | 500                                                   | 400                                                                                                                       |
| Production startup                        | started with missing secrets                          | fails when a required secret is missing, short or `change-me`, or when no dashboard origin is set                         |

## Consequences

- Frontends must stop sending `imageId` and cover urls that are not already stored for the user. The apps use mock data today, so nothing breaks yet.
- **Heads-up for frontend wiring:** tokens without an `azp` claim now get 401 (Clerk rejects a missing `azp` once `authorizedParties` is set, and the match is exact). This has not been verified with real Clerk tokens. Verify it with real session tokens from each dashboard origin when the apps start calling the API, and confirm that every origin that calls the API is in the dashboard origin list. Non-browser clients must send a token with an `azp` claim.
- Every `isAuthenticated` route requires an existing account for the claimed role.
- Resend cannot run within 60 seconds of creating an invitation, because creating one also sets `updated_at`.
- Not verified without running services: Clerk `azp` behaviour with real tokens, ImageKit behaviour on delete, production boot with the real environment.
