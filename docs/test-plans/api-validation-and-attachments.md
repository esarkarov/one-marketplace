# Test plan: API validation, logging and attachments (Stage 3b)

## Scope

Uncommitted Stage 3b work in `services/api`: zod env validation (`config/env.ts`), `validate` middleware and jobs schemas, pino logging with redaction (`config/logger.ts`, http logger), auth split into `verifyBearerToken` and `resolveAccountRole` with large-body routes parsed after auth, attachment upload helpers (`utils/attachments.ts`), Redis auth cache with invalidation hooks, and admin `/logs/stream` replaced by a 503. Tools: vitest and supertest (existing). Related: `api-hardening.md`.

Result: 225 tests in 16 files pass. Coverage (v8): statements 29.17%, branches 12.27%, functions 21.13%, lines 29.86%. Lowest files: `server.ts`, `events/consumer.ts`, `payouts.*` (0%); `contracts.service.ts` 4%, messaging service and socket about 7%, `admin.service.ts` 10%, `auth.controller.ts` 11%. New Stage 3b code is mostly well covered (env 100%, middleware about 87%, utils about 87%), except `jobs.service.ts` (30%) and `messaging.service.ts` (7%).

## Blocked on "to confirm" business rules

- 3: intended onboarding order for freelancers and agencies.
- 9: attachment size and count limits (also hardening scenario 9).
- 10: choice of log viewer replacement.
- 18: role change and account deletion are not implemented; needs a product and infra decision.
- Any fee, escrow, payout or dispute assertion on job or message flows is blocked until `docs/product.md` confirms the rules.

## Notes

- Overall coverage is low by design: most modules (contracts, proposals, payouts, admin) have no tests yet.
- E scenarios need a Clerk test token and ImageKit credentials supplied by the owner; QA does not read `.env`.
