# api-change

Follow in order. Standing rules and tier definitions are in `AGENTS.md`; do not restate them.

1. Scope: name the slice and the files. If application source is not yet approved, ask first. Use the `explorer` agent for "where is X" questions.
2. Read: `services/api/AGENTS.md`, the module fully, the ADRs the slice touches (`ls docs/decisions`, then Grep), the existing tests in `src/modules/<name>/tests/` and `src/test/architecture/`. For a new module or route also `docs/adding-an-api-module.md`.
3. Implement with the `backend` agent (the `database` agent for schema). Layering, repositories, ownership and money rules: `references/checklist.md`.
4. Migration (only if the schema changes): `/db-change`. Generated by drizzle-kit against local Docker, append-only, never edit an applied file (hook blocks it).
5. OpenAPI (only if routes or schemas changed): record `sha256sum docs/api/openapi.json`, run `pnpm --filter @onemarketplace/api openapi:generate`, then `pnpm --filter @onemarketplace/api-client generate`; the sha must change only when the contract changed.
6. Tests: unit, validation, contract (parses real responses with the response schemas) and, for ordering, money or security logic, a mutation check (break the code, see the test fail).
7. Tier 1 through `/verify`: affected module tests, API typecheck, eslint on touched files, openapi drift. Fix, rerun.
8. Docs: an ADR note when a decision changed (`adr` skill); `docs/frontend-integration-notes.md` when a response shape or status changed; the nested `AGENTS.md` when a rule changed.
9. Tier 2 when the slice is finished: `pnpm --filter @onemarketplace/api test:quiet`, `pnpm check`, one `reviewer` pass.
10. Compact report (format in `AGENTS.md`), then `/commit-plan`. Never commit.
